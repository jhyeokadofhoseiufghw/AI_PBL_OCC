# 10. MVP 범위 / 일정 / 우선순위

## 1. MVP 핵심 기능 3개로 요약

실제 데모 기준에서 가장 중요한 핵심 기능 3개는 아래다.

### 핵심 기능 1. 기획자 공연 생성 및 운영 관리

- 회원가입 / 로그인
- 공연 생성
- 좌석 생성
- 공연 단일 티켓 가격 설정
- 티켓 타입 설정
- 공연 상태 관리
- 예매자 목록 조회

### 핵심 기능 2. 비회원 예매 + 입금 승인 + 예매번호/QR 발급

- 관객 비회원 예매
- 승인 여부 확인
- 상세 조회
- 기획자 입금 승인
- 예매번호/QR 발급

### 핵심 기능 3. QR 체크인 + 홈 피드 기반 공연 유입

- 메인 홈 피드
- QR 스캔 체크인

## 4. 4일 개발 로드맵

### 일정 배분 원칙

- 작업량 목표는 **Day 1 25% / Day 2 30% / Day 3 27% / Day 4 18%**로 둔다.
- Day 1~3에 데모 핵심 흐름을 연결하고, Day 4는 체크인 완성 및 통합 QA에 집중한다.
- 각 날짜의 완료 기준을 통과하지 못하면 P1 운영 편의 기능보다 핵심 흐름 복구를 우선한다.

### Day 1 — 기반 구축 + 공연 초안 생성 (25%)

#### 구현

- 프로젝트 세팅, 환경 변수 검증, 공통 레이아웃 / 오류 처리 기반 구성
- Neon DB 스키마, enum, FK, unique / check 제약, 주요 인덱스 생성
- Organizer 회원가입 / 로그인 / 로그아웃, 비밀번호 해시, 세션, 대시보드 보호 라우트
- Organizer가 본인 데이터만 다루도록 서버 액션 권한 검증 공통 함수 구성
- 공연 생성 / 목록의 최소 기능
  - 공연 필수 정보, 단일 티켓 가격, 계좌 정보, 예매 방식 저장
  - 티켓 타입 및 단순 좌석 라벨 생성
  - `HIDDEN` 상태 임시 저장과 고유 slug 생성
- 포스터 / 피드 이미지는 외부 저장소 연동 여부를 확정하고, 미연동 시 URL 입력 방식으로 고정

#### 완료 기준

- 회원가입 → 로그인 → 보호된 대시보드 → 비공개 공연 1개 생성이 가능하다.
- 다른 Organizer의 공연을 조회하거나 수정할 수 없다.
- 좌석 라벨 중복, 잘못된 가격/수용 인원 등 핵심 DB 제약이 동작한다.

### Day 2 — 공연 공개 + 관객 예매 완성 (30%)

#### 구현

- 공연 수정 / 상태 관리, 관객용 모바일 미리보기, 필수값 검증 후 공개
- 공개 공연 상세, 공개 URL 복사, 러닝타임 / 취소 정책 / 계좌 / 잔여 수량 표시
- 피드 게시글 작성 / 수정 / 삭제, 공연별 최대 3개 제한, 홈 통합 피드 최신순 노출
- 비회원 예매 UI
  - 계좌 정보 확인 → 최종 예매 신청의 2단계 액션
  - 선착순 매수 선택과 좌석 지정 복수 좌석 선택
  - 티켓 타입 선택, 조회 패스워드, 요청사항, 서버 기준 금액 계산
- 예매 생성 트랜잭션
  - 최대 매수와 잔여 수량 검증
  - 좌석 잠금 / partial unique를 통한 동시 중복 점유 방지
  - 조회 패스워드 해시 및 예매 시점 단가/총액 저장

#### 완료 기준

- 기획자가 공연을 미리본 뒤 공개하고 피드 글을 작성할 수 있다.
- 관객이 홈 피드 → 공연 상세 → 선착순 또는 좌석 지정 예매를 완료할 수 있다.
- 동시 요청에도 초과 예매와 동일 좌석 중복 점유가 발생하지 않는다.

### Day 3 — 예매 운영 + QR 발급 + 관객 사후 처리 (27%)

#### 구현

- 기획자 예매자 목록, 필수 컬럼, 입금자명/연락처 검색, 상태 필터
- 입금 승인 트랜잭션
  - `CONFIRMED` 전환
  - 고유 예매번호와 추측 불가능한 `qr_token` 생성
  - `python-qrcode` 기반 QR 이미지 생성 및 실패/재시도 상태
- 이름 + 정규화된 연락처 + 조회 패스워드 기반 전역 승인 확인 / 복수 결과 선택 / 상세 조회
- 확정 또는 입장 완료 예약에만 QR 노출
- 취소 마감 검증, 직접 취소, 좌석 `released_at` 기록 및 수량 복구
- 승인 취소 시 기존 QR 즉시 무효화, 입장 완료 건 승인 취소 차단
- 매진 시 대기 신청과 기획자의 대기 목록 조회 / 수동 전환 최소 흐름

#### 완료 기준

- 예매 신청 → 입금 승인 → 예매번호 확인 → 상세 조회 / QR 표시가 연결된다.
- 승인 전, 취소, 대기 상태의 QR은 노출되거나 유효하지 않다.
- 취소한 좌석/수량은 다시 예매할 수 있고 과거 좌석 이력은 보존된다.

### Day 4 — 체크인 + 통계 + 통합 QA (18%)

#### 구현

- `@yudiel/react-qr-scanner` 기반 QR 체크인
  - 후면 카메라 우선, QR 형식 제한, 처리 중 일시 정지 / 재개
  - 카메라 권한 거부, 미지원 브라우저, 비 HTTPS 환경 오류 처리
  - 공연 소유권 / eventId 일치 / 예약 상태 검증
  - 체크인 상태와 시각을 같은 트랜잭션에서 기록하고 중복 입장 차단
- 대시보드 핵심 KPI와 공연별 최소 통계
- 로그인 및 예약 조회 rate limit 등 최소 악용 방지 적용
- 모바일 핵심 화면 점검, 접근 권한 / 실패 상태 / 빈 상태 보완
- 핵심 플로우 통합 테스트, 데모 데이터와 데모 시나리오 리허설

#### 완료 기준

- 실제 HTTPS 모바일 환경에서 QR 발급 → 스캔 → 입장 완료 → 중복 차단이 동작한다.
- 다른 공연 QR, 취소 QR, 승인 전 QR, 다른 Organizer의 요청이 모두 거부된다.
- 문서의 데모 시나리오 8단계를 처음부터 끝까지 재현할 수 있다.

### 4일 내 범위 조정 순서

일정이 밀릴 경우 아래 순서로 축소하며, 핵심 데모 흐름은 유지한다.

1. **P2로 이동**: UI polish, 검색/필터 고도화
2. **P1로 이동**: 일괄 승인/취소, 엑셀 다운로드, 페이지네이션, 카메라 선택 고도화
3. **단순화**: 대기열은 목록 조회와 단건 수동 전환만 제공
4. **유지해야 할 P0**: 인증, 공연 생성/공개, 예매, 입금 승인, 안전한 조회, QR 발급, QR 체크인, 취소/좌석 복구

### 구현 순서 판단 기준

1. 데모 시나리오를 완성하는가?

4. 4일 안에 구현 가능한가?
