# 08. 인증 / 권한 / 보안 정책

## 1. 인증 정책

### Organizer

- 이메일 + 비밀번호 로그인
- 회원가입·이메일 변경·비밀번호 재설정에 5분 유효 이메일 인증번호 사용
- 인증번호는 원문이 아닌 HMAC 해시로 저장하고 성공 시 일회성 소진
- 비밀번호 재설정 발송 단계는 가입 여부를 노출하지 않는 동일 응답 사용
- 보호된 대시보드 접근

### Audience

- 회원가입 없음
- 비회원 예매

---

## 2. 권한 정책

## Organizer 권한

- 본인이 생성한 공연만 관리 가능
- 본인 공연의 단일 티켓 가격 / 좌석 / 티켓 타입 / 피드 / 예매 / 체크인 관리 가능

## Audience 권한

- 공개 공연 조회 가능
- 자신의 예약만 조회 가능
- 자신의 예약만 취소 가능

---

## 3. 예약 조회 보안 정책

조회 패스워드는 예매 시 관객이 설정하는 숫자 4~6자리 값이며, 서버에서 형식 검증 후 해시만 저장한다.

## 승인 여부 확인 페이지

입력:

- 이름
- 연락처
- 조회 패스워드

허용 기능:

- 승인 여부 확인
- 승인 완료 시 예매번호 확인

## 상세 조회 페이지

입력:

- 이름
- 연락처
- 조회 패스워드

허용 기능:

- 예약 상세 조회
- 예매 확정 상태의 QR 확인
- 취소 가능 여부 확인
- 취소 수행

### 조회 패스워드 분실 복구

- 이메일·SMS 인증을 예매 단계에 추가하지 않는 대신 기획자가 저장된 연락처로 역전화 확인한다.
- 이름과 연락처만으로는 초기화할 수 없고, 로그인한 기획자가 본인 공연의 활성 예매에 대해서만 수행한다.
- 임시 6자리 패스워드는 한 번만 표시하고 해시만 저장하며, 관객이 새 패스워드로 변경하기 전에는 상세·QR·취소 접근을 허용하지 않는다.
- 초기화 시각과 수행 기획자를 기록하고 예약별 발급 횟수를 제한한다.

## 4. 체크인 보안 정책

- QR는 예매 확정 상태에서만 유효
- 이미 체크인된 티켓 QR은 재사용 불가하며 같은 예매의 미사용 QR에는 영향을 주지 않음
- 입장 취소는 해당 공연 소유 Organizer만 수행할 수 있으며 취소 후 해당 QR은 다시 사용 가능
- 취소된 예약의 QR는 무효
- 체크인 스캐너는 Organizer 보호 라우트에서만 접근 가능
- 체크인 처리 시 라우트의 eventId와 QR의 eventId가 일치해야 함
- 체크인 처리 시 로그인한 Organizer가 해당 공연 소유자인지 검증해야 함
- 휴대폰 카메라 접근을 위해 체크인 페이지는 HTTPS 환경에서 제공
- QR 스캔 결과는 개인정보가 아니라 `qr_token`만 포함해야 함

## 5. 데이터 접근 제어 제안

Neon DB 연결은 서버 전용으로만 사용한다.  
데이터 접근 제어는 Server Actions와 서버 전용 DB 클라이언트에서 명시적으로 검증한다.

### organizers

- 본인만 읽기/수정 가능

### events

- 공개 공연은 관객 읽기 가능
- 기획자는 본인 공연만 수정 가능

### reservations

- 기획자는 본인 공연의 예약만 조회 가능
- 관객은 이름/연락처/조회 패스워드 검증을 통과한 예약만 접근 가능

### feed_posts

- 공개 공연의 피드는 읽기 가능
- 기획자는 본인 공연의 피드만 작성/수정 가능

## 6. 비밀번호 / 민감정보 정책

- 비밀번호는 반드시 해시 저장
- 이메일 인증번호는 최대 5회 검증, 60초 재발송 제한, 5분 만료 적용
- 관객 조회 패스워드도 원문 저장 금지, 해시로만 저장
- 임시 조회 패스워드 역시 원문 저장 금지 및 최초 사용 시 변경 강제
- 입금 계좌 정보는 기획자만 수정 가능
- 연락처는 최소 노출 원칙 유지

---

## 7. 악용 방지 최소 정책

4일 MVP 기준에서 아래 정도를 최소 반영 권장:

- 로그인 rate limit 또는 기본적인 brute-force 방지
- 이메일 인증번호 발송과 비밀번호 재설정 rate limit
- 승인 여부 확인 / 상세 조회 페이지에 과도한 요청 방지
- 기획자 조회 패스워드 임시 발급은 예약별 15분에 3회로 제한
- QR 토큰은 추측 불가능한 랜덤값 사용
