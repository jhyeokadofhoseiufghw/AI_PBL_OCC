# 08. 인증 / 권한 / 보안 정책

## 1. 인증 정책

### Organizer
- 이메일 + 비밀번호 로그인
- 보호된 대시보드 접근

### Audience
- 회원가입 없음
- 비회원 예매

---

## 2. 권한 정책

## Organizer 권한
- 본인이 생성한 공연만 관리 가능
- 본인 공연의 좌석 / 티켓 타입 / 피드 / 예매 / 체크인 관리 가능

## Audience 권한
- 공개 공연 조회 가능
- 자신의 예약만 조회 가능
- 자신의 예약만 취소 가능

---

## 3. 예약 조회 보안 정책

## 승인 여부 확인 페이지
입력:
- 이름
- 연락처
- 조회 패스워드

허용 기능:
- 승인 여부 확인
- 승인 완료 시 예매번호 확인

## 상세 조회 페이지
입력:
- 이름
- 연락처
- 조회 패스워드

허용 기능:
- 예약 상세 조회
- QR 확인
- 취소 가능 여부 확인
- 취소 수행

---

## 4. 체크인 보안 정책
- QR는 예매 확정 상태에서만 유효
- 이미 체크인된 QR는 재사용 불가
- 취소된 예약의 QR는 무효
- 체크인 스캐너는 Organizer 보호 라우트에서만 접근 가능
- 휴대폰 카메라 접근을 위해 체크인 페이지는 HTTPS 환경에서 제공
- QR 스캔 결과는 개인정보가 아니라 `qr_token`만 포함해야 함

---

## 5. 데이터 접근 제어 제안

Neon DB 연결은 서버 전용으로만 사용한다.  
데이터 접근 제어는 Server Actions와 서버 전용 DB 클라이언트에서 명시적으로 검증한다.

### organizers
- 본인만 읽기/수정 가능

### events
- 공개 공연은 관객 읽기 가능
- 기획자는 본인 공연만 수정 가능

### reservations
- 기획자는 본인 공연의 예약만 조회 가능
- 관객은 이름/연락처/조회 패스워드 검증을 통과한 예약만 접근 가능

### feed_posts
- 공개 공연의 피드는 읽기 가능
- 기획자는 본인 공연의 피드만 작성/수정 가능

---

## 6. 비밀번호 / 민감정보 정책
- 비밀번호는 반드시 해시 저장
- 관객 조회 패스워드도 원문 저장 금지, 해시로만 저장
- 입금 계좌 정보는 기획자만 수정 가능
- 연락처는 최소 노출 원칙 유지

---

## 7. 악용 방지 최소 정책
4일 MVP 기준에서 아래 정도를 최소 반영 권장:
- 로그인 rate limit 또는 기본적인 brute-force 방지
- 승인 여부 확인 / 상세 조회 페이지에 과도한 요청 방지
- QR 토큰은 추측 불가능한 랜덤값 사용
