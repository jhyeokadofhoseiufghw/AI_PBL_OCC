# 11. Open Questions / 추후 확장

이 문서는 **현재까지 사용자와 확정되지 않았거나, MVP에서 보수적으로 남겨둔 항목**을 정리한다.

---

## 1. 대기열 상세 UX

아직 미정인 항목:

- 대기 신청 시 입력 항목을 일반 예매와 동일하게 받을지
- 좌석 지정 공연에서 대기자를 전환할 때 좌석을 다시 고르게 할지
- 대기 신청에서 입금 대기 전환 시 정확한 플로우

### 현재 PRD의 보수적 해석

- MVP에서는 `대기 신청` 상태의 예약으로 저장
- 전환은 기획자가 수동으로 처리
- 좌석 지정 공연의 전환 세부 UX는 구현 시 단순화 가능

---

## 2. 취소 후 환불 안내 문구

현재 확정된 것:

- 관객은 취소 가능 시간 내 직접 취소 가능

아직 미정인 것:

- 취소 후 환불 프로세스를 시스템에 어떻게 노출할지
  - 예: "환불은 기획자에게 문의해주세요"

### PRD 기본 권장안

- MVP에서는 취소 완료 후 "환불 관련 사항은 공연 주최자에게 문의" 문구를 노출

---

## 3. 피드 정렬 정책

현재 확정된 것:

- 피드 게시글은 메인 홈 통합 피드에만 노출
- 공연별 대표 피드 1개만 등록 가능

아직 미정인 것:

- 정렬 기준
  - 최신순 고정
  - 중요 게시물 고정
  - 공연 시작일 기반 보정

### PRD 기본 권장안

- MVP에서는 **최신순 정렬**로 고정

---

## 4. 공연 상태 자동 전환의 정확한 기준

현재 확정된 것:

- 예정 → 진행 중 → 종료 자동 전환 가능

아직 구현 시 정해야 하는 것:

- 진행 중 전환 기준을 `event_start_at`으로 할지
- 종료 기준을 `event_end_at` 또는 수동 종료로 할지

### PRD 기본 권장안

- `event_start_at` 이후 `IN_PROGRESS`
- `event_end_at` 이후 `COMPLETED`
- `event_end_at`이 없으면 수동 종료 허용

---

## 5. 예약 조회 보안 강화 여부

현재 구조:

- 승인 여부 확인: 이름 + 연락처 + 조회 패스워드
- 상세 조회: 이름 + 연락처 + 조회 패스워드 + 목록에서 선택한 예약 ID

확정된 정책:

- 조회 패스워드는 예매 신청 시 관객이 설정한다.
- 이름 + 정규화된 연락처 + 조회 패스워드로 전체 공연의 예약을 조회한다.
- 복수 결과는 공연 정보가 포함된 목록으로 제공하고 인증된 후보만 상세 조회한다.

추후 고려 가능:

- 1회용 조회 링크
- 문자 인증
- OTP

단, MVP에서는 제외한다.

---

## 6. 단일 티켓 가격과 할인 정책 확장

현재 확정된 것:

- 선착순/좌석 지정 공연 모두 공연별 단일 티켓 가격을 사용한다.
- 총액은 `공연 단일 가격 × 예매 매수`로 계산한다.
- 예매 시점의 단가와 총액을 저장해 이후 가격 변경이 기존 예매에 영향을 주지 않게 한다.

MVP에서 제외하는 것:

- 좌석별/좌석 등급별/티켓 타입별 차등 가격
- 학생/조기예매/쿠폰 같은 할인 정책

추후 확장 시에는 별도 가격 정책 또는 할인 정책 테이블을 두는 것을 검토한다.

---

## 7. Design ↔ PRD 정합성 확정사항 (2026-07-10)

기존 충돌 항목은 아래 기준으로 확정했으며 design과 PRD에 반영했다.

### 7-1. 시스템 최고 관리자 제외

- MVP 권한은 Organizer / Audience / System으로 한정한다.
- 최고 관리자, 공연 강제내림, 전사 검색, 기획자 계정 발급 화면은 제공하지 않는다.

### 7-2. 장기 미입금 수동 처리

- 미입금 건은 자동 취소하지 않는다.
- 기획자가 예매 관리 화면에서 직접 취소하며 좌석/수량과 상태 이력을 보존한다.

### 7-3. 단일 티켓 가격 계산

- 공연별 단일 가격 `P`를 사용한다.
- 선착순/좌석 지정 모두 `총액 = P × 예매 매수 N`으로 계산한다.

### 7-4. 단순 좌석 목록 편집

- 복잡한 행×열 맵 에디터와 통로 토글은 MVP에서 제외한다.
- 좌석 라벨 목록 추가/수정/비활성화만 제공한다.

### 7-5. 예매 일괄 취소

- 영구 삭제는 제공하지 않는다.
- 일괄 취소 시 좌석/수량을 복구하고 상태 이력을 보존한다.

### 7-6. 평점 제외 및 인기 공연

- 관객 평점 입력과 별점 표시는 MVP에서 제외한다.
- 인기 공연은 예매 수를 기준으로 표시한다.

### 7-7. PRD 라우트와 조회 인증 사용

- 공연 상세는 `/events/[eventSlug]`를 사용한다.
- 예약 조회는 이름/정규화된 연락처/조회 패스워드를 검증하고 복수 결과를 목록으로 제공하며, 인증된 후보의 reservationId만 상세 조회한다.

### 7-8. 정적 QR 정책

- 캡처본 제한 문구는 사용하지 않는다.
- 추측 불가능한 정적 `qr_token`과 체크인 후 중복 사용 차단을 적용한다.
