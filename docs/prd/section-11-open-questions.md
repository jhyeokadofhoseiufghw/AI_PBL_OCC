# 11. Open Questions / 추후 확장

이 문서는 **현재까지 사용자와 확정되지 않았거나, MVP에서 보수적으로 남겨둔 항목**을 정리한다.

---

## 1. 대기열 상세 UX

아직 미정인 항목:
- 대기 신청 시 입력 항목을 일반 예매와 동일하게 받을지
- 좌석 지정 공연에서 대기자를 전환할 때 좌석을 다시 고르게 할지
- 대기 신청에서 입금 대기 전환 시 정확한 플로우

### 현재 PRD의 보수적 해석
- MVP에서는 `대기 신청` 상태의 예약으로 저장
- 전환은 기획자가 수동으로 처리
- 좌석 지정 공연의 전환 세부 UX는 구현 시 단순화 가능

---

## 2. 취소 후 환불 안내 문구

현재 확정된 것:
- 관객은 취소 가능 시간 내 직접 취소 가능

아직 미정인 것:
- 취소 후 환불 프로세스를 시스템에 어떻게 노출할지
  - 예: "환불은 기획자에게 문의해주세요"

### PRD 기본 권장안
- MVP에서는 취소 완료 후 "환불 관련 사항은 공연 주최자에게 문의" 문구를 노출

---

## 3. 피드 정렬 정책

현재 확정된 것:
- 메인 홈 피드와 공연 상세 피드 둘 다 존재

아직 미정인 것:
- 정렬 기준
  - 최신순 고정
  - 중요 게시물 고정
  - 공연 시작일 기반 보정

### PRD 기본 권장안
- MVP에서는 **최신순 정렬**로 고정

---

## 4. 공연 상태 자동 전환의 정확한 기준

현재 확정된 것:
- 예정 → 진행 중 → 종료 자동 전환 가능

아직 구현 시 정해야 하는 것:
- 진행 중 전환 기준을 `event_start_at`으로 할지
- 종료 기준을 `event_end_at` 또는 수동 종료로 할지

### PRD 기본 권장안
- `event_start_at` 이후 `IN_PROGRESS`
- `event_end_at` 이후 `COMPLETED`
- `event_end_at`이 없으면 수동 종료 허용

---

## 5. 예약 조회 보안 강화 여부

현재 구조:
- 승인 여부 확인: 공연 식별자 + 이름 + 연락처 + 조회 패스워드
- 상세 조회: 공연 식별자 + 이름 + 연락처 + 조회 패스워드

확정된 정책:
- 조회 패스워드는 예매 신청 시 관객이 설정한다.
- 조회는 특정 공연 컨텍스트 안에서 수행한다.
- 이름 + 연락처 + 조회 패스워드만 사용하는 전역 단일 예약 조회는 허용하지 않는다.

추후 고려 가능:
- 1회용 조회 링크
- 문자 인증
- OTP

단, MVP에서는 제외한다.

---

## 6. 좌석 등급 가격과 할인 정책 확장

현재 확정된 것:
- 선착순 공연은 티켓 타입 가격을 사용한다.
- 좌석 지정 공연은 선택한 좌석의 좌석 등급 가격을 사용한다.
- 예매 시점의 단가와 총액을 저장해 이후 가격 변경이 기존 예매에 영향을 주지 않게 한다.

MVP에서 제외하는 것:
- 좌석 등급 + 티켓 타입 조합별 가격
- 학생/조기예매/쿠폰 같은 할인 정책
- 좌석 등급별 잔여 수량 별도 관리

추후 확장 시에는 `seat_grade_ticket_prices` 또는 할인 정책 테이블을 별도로 두는 것을 검토한다.
