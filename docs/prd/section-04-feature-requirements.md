# 04. 기능 요구사항 (핵심 기능 상세)

## 1. 기능 목록

MVP 핵심 기능은 아래 6개 묶음으로 구성한다.

1. **기획자 인증 및 대시보드**
2. **공연 생성 / 관리**
3. **피드형 공연 홍보**
4. **비회원 예매 / 조회 / 취소**
5. **입금 승인 / 대기열 관리**
6. **QR 체크인**

---

# 2. 기능 A — 기획자 인증 및 대시보드

## 목적

기획자가 공연 운영 도구에 접근할 수 있어야 한다.

## 요구사항

- 이메일 + 비밀번호 회원가입 / 로그인
- 회원가입 필드:
  - 이메일
  - 비밀번호
  - 이름
  - 연락처
  - 단체명
- 로그인 후 보호된 대시보드 접근 가능
- 대시보드 첫 화면은 **전체 통계 우선**

## 대시보드 KPI 예시

- 총 공연 수
- 예정 공연 수
- 진행 중 공연 수
- 종료 공연 수
- 입금 대기 수
- 예매 확정 수
- 오늘 체크인 수
- 대기 신청 수

---

# 3. 기능 B — 공연 생성 / 관리

## 목적

기획자가 여러 공연을 생성하고 운영할 수 있어야 한다.

## 공연 생성 필수 입력

- 공연명
- 날짜/시간
- 장소
- 공연 상세 설명
- 포스터 이미지
- 단일 티켓 가격
- 입금 계좌
- 예매 방식
  - 선착순
  - 좌석 지정
- 총 수용 인원(선착순 공연 필수, 좌석 지정 공연은 활성 좌석 수로 계산)
- 최대 예매 가능 매수
- 취소 가능 마감 시간

## 공연 상태

- 예정
- 진행 중
- 종료
- 비공개
- 취소

## 공연 공개 URL

- 공연마다 공개 URL 생성
- 외부 공유 가능
- 공연 상세 상단에서 공유 링크 복사 가능

## 저장 / 미리보기 / 공개

- 생성 중인 공연은 `비공개(HIDDEN)` 상태로 임시 저장 가능
- 공개 전 관객용 공연 상세 화면을 모바일 크기로 미리보기 가능
- 공개 시 공연 시작 전이면 `예정(SCHEDULED)` 상태로 전환

## 공연 기본 콘텐츠

- 대표 포스터는 세로형 A3 비율(1:1.414) 슬롯 사용
- 대표 포스터와 상세 설명용 피드 이미지는 서로 독립된 입력/저장 필드로 관리
- 러닝타임과 취소 정책, 입금 계좌, 실시간 잔여 좌석/수량을 상세 화면에 노출

## 좌석 지정 공연 추가 요구사항

- 좌석 생성 기능 제공
- 기획자가 A1, A2 같은 좌석 라벨을 직접 생성
- 최초 공연 생성 화면에서 행·열 기반 좌석 배치도를 만들 수 있어야 함
- 배치도에서 좌석을 해제해 통로 또는 빈 공간을 표현할 수 있어야 함
- 저장된 좌석의 행·열 위치는 관객 예매 화면의 좌석 선택 배치에도 동일하게 반영
- 생성 이후 좌석 관리 화면도 리스트가 아닌 무대 기준 N×N 배치도로 표시하고, 각 셀에서 라벨 수정과 활성화·비활성화를 지원
- 최초 공개 전에는 좌석 관리 화면에서 생성 단계와 같은 배치도 제작기로 좌석 전체를 다시 만들 수 있음
- 최초 공개 시각을 기록하며, 최초 공개 후에는 다시 비공개로 전환하더라도 좌석 배치·라벨·활성 상태를 변경할 수 없음
- 모든 좌석은 공연에 설정된 동일한 티켓 가격 사용

## 티켓 타입

- 공연마다 여러 티켓 타입 생성 가능
  - 일반 / 학생 등
- 각 티켓 타입에 0원 이상의 개별 가격 설정 가능
- 티켓 타입별 수량은 관리하지 않음
- 관객이 선택한 티켓 타입의 가격으로 예매 금액 계산
- 티켓 타입이 없는 공연은 공연 기본 가격 사용
- 타입 가격 변경은 신규 예매에만 적용하고 기존 예매 금액은 유지

# 4. 기능 C — 피드형 공연 홍보

## 목적

공연 홍보와 공연 발견을 한 제품 안에서 해결한다.

## 요구사항

- 기획자는 공연별 피드 게시글 작성 가능
- 게시글 구성:
  - 이미지 1개
  - 텍스트 본문

## 노출 위치

### 메인 홈 피드

- 여러 공연의 피드 게시글을 통합 피드로 노출

### 공연 상세 피드

- 특정 공연에 속한 게시글만 노출

## MVP 범위

- 게시글 작성
- 이미지 업로드
- 본문 작성
- 홈 피드 노출
- 공연 상세 피드 노출

## MVP 제외

- 좋아요
- 댓글
- 팔로우
- 알림
- 관객 평점 입력 및 평점 기반 인기 순위 산정

## 홈 탐색 확장(P1)

- 추천 공연 히어로 배너
- 장르 카테고리 필터
- 인기 공연 영역은 예매 수 기반으로 구성

---

# 5. 기능 D — 비회원 예매 / 조회 / 취소

## 목적

관객이 회원가입 없이 공연을 예매하고 관리할 수 있어야 한다.

## 예매 입력 정보

### 필수

- 이름
- 연락처
- 예매 매수
- 입금자명
- 조회 패스워드

### 선택

- 요청사항

## 예매 UI

- 공연 상세에서 예매 CTA를 누르면 모바일 하단 드로어/바텀시트로 예매 UI를 열 수 있음
- 계좌 정보 확인과 최종 예매 신청을 명확한 두 단계 액션으로 구분
- 계좌 정보에는 은행명, 계좌번호, 예금주, 최종 입금 금액을 표시

---

## 예매 방식 1: 선착순 공연

### 플로우

1. 티켓 타입이 설정된 경우 타입 선택
2. 예매 매수 선택
3. 신청 정보 입력
4. 예매 신청
5. 입금

### 잔여 수량

- `총 수용 인원 - 취소/대기 신청을 제외한 예매 수량 합계`로 계산
- 잔여 수량보다 큰 예매 요청은 거부

---

## 예매 방식 2: 좌석 지정 공연

### 플로우

1. 예매 가능한 좌석 선택
2. 선택 좌석 기준 총액 확인
3. 티켓 타입이 설정된 경우 타입 선택
4. 신청 정보 입력
5. 예매 신청
6. 입금

### 좌석 점유

- 한 예매에서 복수 좌석 선택 가능
- 선택 좌석은 예매-좌석 연결 테이블에 저장
- 입금 대기와 예매 확정 상태 모두 좌석을 점유하며, 취소 시 연결의 해제 시각을 기록해 점유를 해제

### 가격 정책

- 선착순/좌석 지정 모두 선택한 티켓 타입 가격 사용(타입이 없으면 공연 기본 가격)
- `total_price = unit_price × quantity`
- 예매 생성 시 `unit_price`와 `total_price`를 저장
- 예매 이후 공연 가격이 변경되어도 기존 예매의 저장 금액은 변경하지 않음

---

## 예매 조회 구조

승인 여부 확인과 상세 조회는 공연 주소 입력 없이 이름·연락처·조회 패스워드로 수행한다. 복수 결과는 공연 목록으로 제시해 사용자가 선택하며 상세/QR 화면에서 다시 목록으로 돌아갈 수 있어야 한다. 연락처는 하이픈을 제거한 숫자 값으로 비교한다.

### 1단계 — 승인 여부 확인 페이지

입력:

- 이름
- 연락처
- 조회 패스워드

결과:

- 입금 승인 여부 확인
- 승인된 경우 예매번호 노출

### 2단계 — 상세 조회 페이지

입력:

- 이름
- 연락처
- 조회 패스워드

결과:

- 예매 상세 확인
- 예매 확정 상태의 QR 확인
- 취소 가능 여부 확인
- 직접 취소

---

## 취소 정책

- 관객은 상세 조회 페이지에서 직접 취소 가능
- 단, 공연별 취소 마감 시간 이전이어야 함
- 취소 시 좌석/수량 복구

---

# 6. 기능 E — 입금 승인 / 대기열 관리

## 목적

기획자가 수동 입금 승인과 매진 공연 대기열을 관리할 수 있어야 한다.

## 입금 승인

- 기획자는 예매자 목록 테이블에서 입금 대기 예매를 확인
- 승인 시:
  - 상태 → 예매 확정
  - 예매번호 생성
  - QR 생성
  - QR 이미지는 서버에서 `python-qrcode` 기반 생성기로 만든다.
- 공연별 예매 목록은 입금자명/연락처 검색과 상태 필터를 지원
- 기획자는 승인 완료 건의 승인을 취소할 수 있으며, 상태 및 QR 유효성 처리 규칙을 함께 적용

## 운영 편의 기능(P1)

- 공연 선택 드롭다운으로 관리 대상을 전환
- 공연별 총 예매/매출, 입금 대기, 승인 완료, 잔여 좌석 요약
- 페이지네이션 및 페이지 크기 선택
- 선택 예매 일괄 승인
- 예매 목록 엑셀 다운로드

- 영구 삭제 대신 일괄 취소를 제공하고 좌석/수량 복구 및 상태 이력을 보존

## 예매 상태

- 입금 대기
- 예매 확정
- 취소
- 입장 완료
- 대기 신청

## 대기열

- 매진 시 관객은 대기 신청 가능
- 기획자는 대기 신청 목록을 확인 가능
- 기획자가 대기자를 수동으로 예매로 전환 가능

# 7. 기능 F — QR 체크인

## 목적

공연 당일 입장 처리를 빠르게 수행한다.

## 요구사항

- 예매 확정 시 예매 매수만큼 티켓과 QR 생성
- 좌석 지정 예매는 각 QR을 하나의 좌석과 연결하고, 선착순 예매는 티켓 순번으로 구분
- QR 이미지는 각 `reservation_tickets.qr_token`을 인코딩한 결과물이어야 함
- 기획자는 체크인 페이지에서 휴대폰 카메라로 QR 스캔
- 체크인 스캐너는 `@yudiel/react-qr-scanner`를 사용
- 기본 카메라는 후면 카메라(`facingMode: 'environment'`)를 우선 사용
- 동일 QR이 연속으로 여러 번 처리되지 않도록 스캔 중에는 일시 정지 처리
- 스캔 즉시 입장 처리
- 티켓별 입장 처리 시 개별 체크인 완료 시각 기록
- 일부 티켓만 체크인되면 예약은 예매 확정 상태를 유지하고, 모든 티켓이 입장하면 예약 전체를 입장 완료로 변경
- 이미 입장한 개별 QR은 중복 차단하며 같은 예매의 다른 미사용 QR은 계속 사용 가능
