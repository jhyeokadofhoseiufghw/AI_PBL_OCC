# 04. 기능 요구사항 (핵심 기능 상세)

## 1. 기능 목록

MVP 핵심 기능은 아래 6개 묶음으로 구성한다.

1. **기획자 인증 및 대시보드**
2. **공연 생성 / 관리**
3. **피드형 공연 홍보**
4. **비회원 예매 / 조회 / 취소**
5. **입금 승인 / 대기열 관리**
6. **QR 체크인**

---

# 2. 기능 A — 기획자 인증 및 대시보드

## 목적
기획자가 공연 운영 도구에 접근할 수 있어야 한다.

## 요구사항
- 이메일 + 비밀번호 회원가입 / 로그인
- 회원가입 필드:
  - 이메일
  - 비밀번호
  - 이름
  - 연락처
  - 단체명
- 로그인 후 보호된 대시보드 접근 가능
- 대시보드 첫 화면은 **전체 통계 우선**

## 대시보드 KPI 예시
- 총 공연 수
- 예정 공연 수
- 진행 중 공연 수
- 종료 공연 수
- 입금 대기 수
- 예매 확정 수
- 오늘 체크인 수
- 대기 신청 수

---

# 3. 기능 B — 공연 생성 / 관리

## 목적
기획자가 여러 공연을 생성하고 운영할 수 있어야 한다.

## 공연 생성 필수 입력
- 공연명
- 날짜/시간
- 장소
- 공연 상세 설명
- 포스터 이미지
- 입금 계좌
- 예매 방식
  - 선착순
  - 좌석 지정
- 최대 예매 가능 매수
- 취소 가능 마감 시간

## 공연 상태
- 예정
- 진행 중
- 종료
- 비공개
- 취소

## 공연 공개 URL
- 공연마다 공개 URL 생성
- 외부 공유 가능

## 좌석 지정 공연 추가 요구사항
- 좌석 생성 기능 제공
- 기획자가 직접 좌석 라벨을 생성
- 예: A1~A10, B1~B10

## 티켓 타입
- 공연마다 여러 티켓 타입 생성 가능
  - 일반 / 학생 / VIP 등
- 티켓 타입별 수량은 관리하지 않음
- 가격 분류용으로만 사용

---

# 4. 기능 C — 피드형 공연 홍보

## 목적
공연 홍보와 공연 발견을 한 제품 안에서 해결한다.

## 요구사항
- 기획자는 공연별 피드 게시글 작성 가능
- 게시글 구성:
  - 이미지 1개 이상
  - 텍스트 본문

## 노출 위치
### 메인 홈 피드
- 여러 공연의 피드 게시글을 통합 피드로 노출

### 공연 상세 피드
- 특정 공연에 속한 게시글만 노출

## MVP 범위
- 게시글 작성
- 이미지 업로드
- 본문 작성
- 홈 피드 노출
- 공연 상세 피드 노출

## MVP 제외
- 좋아요
- 댓글
- 팔로우
- 알림

---

# 5. 기능 D — 비회원 예매 / 조회 / 취소

## 목적
관객이 회원가입 없이 공연을 예매하고 관리할 수 있어야 한다.

## 예매 입력 정보
### 필수
- 이름
- 연락처
- 예매 매수
- 입금자명
- 조회 패스워드

### 선택
- 요청사항

---

## 예매 방식 1: 선착순 공연
### 플로우
1. 티켓 타입 선택
2. 예매 매수 선택
3. 신청 정보 입력
4. 예매 신청
5. 입금

---

## 예매 방식 2: 좌석 지정 공연
### 플로우
1. 좌석 선택
2. 티켓 타입 선택
3. 신청 정보 입력
4. 예매 신청
5. 입금

---

## 예매 조회 구조

### 1단계 — 승인 여부 확인 페이지
입력:
- 이름
- 연락처
- 조회 패스워드

결과:
- 입금 승인 여부 확인
- 승인된 경우 예매번호 노출

### 2단계 — 상세 조회 페이지
입력:
- 이름
- 연락처
- 조회 패스워드

결과:
- 예매 상세 확인
- QR 확인
- 취소 가능 여부 확인
- 직접 취소

---

## 취소 정책
- 관객은 상세 조회 페이지에서 직접 취소 가능
- 단, 공연별 취소 마감 시간 이전이어야 함
- 취소 시 좌석/수량 복구

---

# 6. 기능 E — 입금 승인 / 대기열 관리

## 목적
기획자가 수동 입금 승인과 매진 공연 대기열을 관리할 수 있어야 한다.

## 입금 승인
- 기획자는 예매자 목록 테이블에서 입금 대기 예매를 확인
- 승인 시:
  - 상태 → 예매 확정
  - 예매번호 생성
  - QR 생성
  - QR 이미지는 서버에서 `python-qrcode` 기반 생성기로 만든다.

## 예매 상태
- 입금 대기
- 예매 확정
- 취소
- 입장 완료
- 대기 신청

## 대기열
- 매진 시 관객은 대기 신청 가능
- 기획자는 대기 신청 목록을 확인 가능
- 기획자가 대기자를 수동으로 예매로 전환 가능

---

# 7. 기능 F — QR 체크인

## 목적
공연 당일 입장 처리를 빠르게 수행한다.

## 요구사항
- 예매 확정 상태에만 QR 존재
- QR 이미지는 `qr_token`을 인코딩한 결과물이어야 함
- 기획자는 체크인 페이지에서 휴대폰 카메라로 QR 스캔
- 체크인 스캐너는 `@yudiel/react-qr-scanner`를 사용
- 기본 카메라는 후면 카메라(`facingMode: 'environment'`)를 우선 사용
- 동일 QR이 연속으로 여러 번 처리되지 않도록 스캔 중에는 일시 정지 처리
- 스캔 즉시 입장 처리
- 이미 입장한 QR은 중복 입장 차단
