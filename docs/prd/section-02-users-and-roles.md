# 02. 사용자 / 역할 / 용어 정의

## 1. Role 정의

### 1) 기획자 (Organizer)

플랫폼의 회원이며, 공연을 생성하고 운영하는 사용자.

#### 권한

- 회원가입 / 로그인
- 공연 생성 / 수정
- 공연 상태 변경
- 좌석 생성
- 공연 단일 티켓 가격 설정
- 티켓 타입 설정
- 공연별 취소 마감 시간 설정
- 공연 홍보 피드 작성
- 예매 현황 조회
- 입금 승인
- 대기열 관리
- QR 체크인
- 통계 대시보드 조회

---

### 2) 관객 (Audience)

회원가입 없이 공연을 조회하고 예매하는 사용자.

#### 권한

- 홈 피드 조회
- 공연 상세 조회
- 공연 피드 조회
- 비회원 예매
- 승인 여부 확인
- 예매번호 확인
- 이름 + 연락처 + 조회 패스워드 기반 승인 여부 확인
- 이름 + 연락처 + 조회 패스워드 기반 상세 조회
- 예매 확정 상태의 QR 확인
- 취소 가능 시간 내 예매 취소

---

### 3) 시스템 (System)

자동 상태 변경, QR 생성 등 자동 처리의 주체.

#### 시스템이 수행하는 일

- 공연 공개 URL 생성
- 공연 상태 자동 변경
- 잔여 좌석 / 잔여 수량 계산
- 예매번호 생성
- QR 생성
- 대기 순번 부여
- 취소 시 좌석/수량 복구

---

## 2. 용어 사전

### Event (공연)

기획자가 생성하는 공연 단위.  
공연명, 일정, 장소, 예매 방식, 피드, 좌석, 예매, 대기열을 포함하는 최상위 도메인.
선착순 공연은 총 수용 인원을 저장하고, 좌석 지정 공연은 활성 좌석 수로 수용 인원을 계산한다.

### Ticket Type (티켓 타입)

일반 / 학생 같은 **예매자 또는 티켓 분류 단위**.  
예매 방식과 관계없이 분류 용도로만 사용하며 타입별 가격은 두지 않는다.

### Seat (좌석)

좌석 지정 공연에서 관객이 선택하는 좌석.  
기획자가 A1, A2, B1 같은 라벨로 직접 생성한다. 모든 좌석은 공연에 설정된 동일한 티켓 가격을 사용한다.
한 예매에서 여러 좌석을 선택할 수 있으며, 선택 관계는 예매-좌석 연결 정보로 저장한다.

### Reservation (예매)

관객의 예매 신청 단위.  
입금 대기 / 예매 확정 / 취소 / 입장 완료 / 대기 신청 상태를 가진다.
예매 생성 시점의 공연 단가와 총액을 함께 저장해, 이후 공연 가격이 바뀌어도 기존 예매 금액이 변하지 않도록 한다.

### Feed Post (피드 게시글)

공연 홍보를 위한 이미지 + 텍스트 게시글.  
공연별 최대 3개까지 등록할 수 있으며 메인 홈 통합 피드에만 노출된다.

## 3. 상태값 정의

## 3-1. 공연 상태 (Event Status)

| 상태    | 설명                      |
| ------- | ------------------------- |
| 예정    | 아직 시작 전인 공연       |
| 진행 중 | 현재 진행 중인 공연       |
| 종료    | 종료된 공연               |
| 비공개  | 기획자가 공개를 숨긴 공연 |
| 취소    | 운영상 취소된 공연        |

### 상태 정책

- `예정 → 진행 중 → 종료` 는 공연 시간 기준 자동 변경 가능
- `비공개`, `취소`는 기획자가 수동으로 변경 가능

---

## 3-2. 예매 상태 (Reservation Status)

| 상태      | 설명                                             |
| --------- | ------------------------------------------------ |
| 입금 대기 | 예매 신청은 했지만 아직 입금 승인 전             |
| 예매 확정 | 기획자가 입금 승인했고 예매번호/QR이 발급된 상태 |
| 취소      | 관객이 직접 취소했거나 운영상 취소 처리된 상태   |
| 입장 완료 | QR 체크인이 완료된 상태                          |
| 대기 신청 | 매진 상태에서 대기열로 신청한 상태               |

### 상태 정책

- 일반 예매: `입금 대기 → 예매 확정 → 입장 완료`
- 취소 발생 시: `취소`
- 매진 시 대기 신청: `대기 신청`
- `입장 완료`로 변경될 때 체크인 완료 시각을 함께 기록한다.

## 4. 비회원 조회 구조 정의

관객은 두 단계로 예매를 확인한다.

조회 패스워드는 관객이 비회원 예매 신청 시 직접 설정하는 필수값이다.  
이 패스워드는 승인 여부 확인, 예매 상세 조회, 취소 권한 확인에 사용하며, 예매번호처럼 입금 승인 후 발급되는 값이 아니다.

조회는 이름 + 연락처 + 조회 패스워드로 전체 공연을 대상으로 수행한다. 같은 정보로 여러 공연 또는 여러 건을 예매한 경우 공연명·공연일·예매일·상태가 포함된 후보 목록을 먼저 표시하고 관객이 원하는 예매를 선택한다. 연락처는 저장·조회 시 숫자만 비교해 하이픈 유무와 관계없이 일치시킨다.

### 1단계: 승인 여부 확인

입력값:

- 이름
- 연락처
- 조회 패스워드

결과:

- 입금 승인 여부 확인
- 승인된 경우 예매번호 확인 가능

### 2단계: 예매 상세 조회

입력값:

- 이름
- 연락처
- 조회 패스워드

결과:

- 예매 상세 조회
- 예매 확정 상태인 경우 QR 확인
- 취소 가능 시간 내 취소

---

## 5. 명시적으로 제외하는 Role

### Admin

플랫폼 운영자 개념의 Admin은 MVP 범위에서 사용하지 않는다.  
현재 시스템의 권한 주체는 **Organizer / Audience / System** 세 가지뿐이다.
