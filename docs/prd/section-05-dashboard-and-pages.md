# 05. 대시보드 / 화면 구조

## 1. 라우트 구조 제안 (Next.js App Router)

```txt
/
├─ /feed                       # 홈 피드 (또는 /)
├─ /events/[eventSlug]         # 공연 상세 + 예매 CTA
├─ /events/[eventSlug]/reserve # 예매 페이지
├─ /reservation/status             # 이름/연락처/조회 패스워드 기반 승인 확인
├─ /reservation/detail             # 전체 예매 목록 선택 + 상세/QR 조회
│
├─ /login
├─ /signup
│
└─ /dashboard
   ├─ /dashboard               # 통계 대시보드
   ├─ /dashboard/events        # 공연 목록
   ├─ /dashboard/events/new    # 공연 생성
   └─ /dashboard/events/[id]
      ├─ /overview             # 공연 개요 / 상태 / 기본 설정
      ├─ /seats                # 좌석 관리
      ├─ /ticket-types         # 티켓 타입
      ├─ /feed                 # 공연 피드 관리
      ├─ /reservations         # 예매자 목록 / 입금 승인 / 취소 / 대기열
      └─ /check-in             # QR 체크인
```

---

## 2. 관객 화면 구조

## 2-1. 홈 피드

### 목적

- 공연 발견
- 공연 홍보 게시글 소비
- 공연 상세로 유입

### 주요 컴포넌트

- 상단 브랜드 헤더
- 로그인 상태별 상단 메뉴
  - 로그인: `예매 조회` / `공연 관리` / `공연 등록 신청`
  - 로그아웃: `예매 조회` / `로그인` / `기획자이신가요?`
  - 각 상태의 마지막 메뉴는 동일한 기본 강조 버튼 스타일 사용
- 추천 공연 히어로 배너
- 인기 공연 영역(예매 수 기반)
- 장르 카테고리 필터
- 공연 피드 카드 리스트
- 공연 카드/피드 카드 클릭 시 공연 상세 이동

---

## 2-2. 공연 상세 페이지

### 목적

- 공연 정보 확인
- 공연 기본 정보와 예매 정책 확인
- 예매 CTA 제공

### 주요 섹션

- 홈 피드와 동일한 로그인 상태별 상단 메뉴
- 포스터 / 공연명 / 일시 / 장소 / 가격 요약
- 러닝타임 / 실시간 잔여 좌석 또는 수량
- 공유 링크 복사
- 상세 설명
- 예매하기 버튼

---

## 2-3. 예매 페이지

### 선착순 공연

- 티켓 타입이 설정된 경우 타입 선택
- 매수 선택
- 선택한 티켓 타입 가격 × 선택 매수 기준 금액 표시
- 신청자 정보 입력
- 조회 패스워드 설정
- 계좌 안내

### 좌석 지정 공연

- 예매 가능 좌석 선택 UI
- 티켓 타입이 설정된 경우 타입 선택
- 선택한 티켓 타입 가격 × 선택 좌석 수 기준 금액 표시
- 신청자 정보 입력
- 조회 패스워드 설정
- 계좌 안내

### 공통 인터랙션

- 모바일에서는 예매 폼을 하단 드로어/바텀시트로 제공 가능
- `계좌 정보 확인 → 최종 예매 신청`의 두 단계 CTA 사용

---

## 2-4. 승인 여부 확인 페이지

입력값:

- 이름
- 연락처
- 조회 패스워드

결과:

- 동일 정보의 복수 예매는 공연 선택 목록 표시
- 승인 대기 / 승인 완료 상태
- 승인 완료 시 예매번호 표시

---

## 2-5. 예매 상세 조회 페이지

입력값:

- 이름
- 연락처
- 조회 패스워드

결과:

- 선택한 예매의 상세 및 티켓별 QR 표시
- QR은 한 장씩 표시하고 좌우 스와이프·이전·다음으로 티켓 전환
- 복수 예매 목록으로 돌아가는 버튼 제공

- 예매 정보
- 예매 확정 상태의 QR
- 취소 버튼(가능 시간 내)

---

# 3. 기획자 화면 구조

## 3-1. 대시보드 홈

### 목적

전체 운영 현황을 빠르게 파악한다.

### KPI 카드 예시

- 총 공연 수
- 예정 공연 수
- 진행 중 공연 수
- 종료 공연 수
- 총 예매 수
- 입금 대기 수
- 예매 확정 수
- 오늘 체크인 수
- 대기 신청 수

### 보조 영역

- 최근 생성한 공연
- 오늘 공연 요약

---

## 3-2. 공연 목록 화면

### 목적

내가 만든 공연을 상태별로 관리한다.

### 리스트 컬럼 예시

- 공연명
- 공연 날짜
- 상태
- 예매 수
- 입금 대기 수
- 체크인 수

---

## 3-3. 공연 상세 운영 화면 탭 구조

### 탭 1. 개요

- 공연 기본 정보
- 상태 변경
- 공개 URL 복사
- 취소 마감 시간 수정
- 임시 저장 / 관객 화면 미리보기 / 공개

### 탭 2. 좌석

- 좌석 생성
- 좌석 목록 확인
- 복잡한 맵 에디터 대신 좌석 라벨 목록 추가/수정/비활성화

### 탭 3. 티켓 타입

- 일반 / 학생 등 생성 및 수정
- 가격 없이 분류 용도로 사용

### 탭 4. 피드

- 공연 피드 게시글 작성 / 수정 / 삭제
- 공연별 최대 3개 등록 가능
- 공연 공개 시 상세 설명을 피드로 자동 생성하지 않으며, 기획자가 광고 목적의 이미지와 문구를 별도로 작성
- 홈 통합 피드에만 노출하며 공연 상세 페이지에는 노출하지 않음

### 탭 5. 예매

- 예매자 목록 테이블
- 입금 승인
- 취소 처리 확인
- 대기 신청 목록 확인
- 대기자 전환
- 입금자명/연락처 검색 및 상태 필터
- 승인 취소 및 QR 조회
- 선택 항목 일괄 승인
- 선택 항목 일괄 취소
- 엑셀 다운로드
- 페이지네이션 / 페이지 크기 선택

### 탭 6. 체크인

- 휴대폰 카메라 QR 스캐너
- 후면 카메라 기본 사용
- 카메라 권한 허용 / 실패 상태 처리
- 체크인 결과 로그
- 체크인 완료 시각 표시
- 최근 체크인 티켓별 입장 취소(확인 대화상자 포함)

# 4. 가장 중요한 화면 우선순위

## 우선순위 1: 대시보드 홈

통계형 KPI가 가장 먼저 보여야 한다.

## 우선순위 2: 공연 상세 > 예매 탭

실무 운영의 핵심은 예매자 목록 테이블이다.

# 5. UI 구현 메모

## 예매자 목록 테이블 필수 액션

- 입금 승인 버튼
- 상태 필터
- 검색
- 대기자 전환 버튼
- 행 클릭 시 상세 모달

## 체크인 화면 필수 UX

- 카메라 미리보기
- 후면 카메라 우선 실행
- 카메라 선택 / 다시 시도 버튼
- 스캔 성공 시 잠시 스캐너 일시 정지
- QR 인식 성공/실패 메시지
- 이미 입장한 QR 경고
