# 05. 대시보드 / 화면 구조

## 1. 라우트 구조 제안 (Next.js App Router)

```txt
/
├─ /feed                       # 홈 피드 (또는 /)
├─ /events/[eventSlug]         # 공연 상세 + 공연 피드 + 예매 CTA
├─ /events/[eventSlug]/reserve # 예매 페이지
├─ /reservation/status         # 이름/연락처/조회 패스워드 기반 승인 여부 확인
├─ /reservation/detail         # 이름/연락처/조회 패스워드 기반 상세 조회
│
├─ /login
├─ /signup
│
└─ /dashboard
   ├─ /dashboard               # 통계 대시보드
   ├─ /dashboard/events        # 공연 목록
   ├─ /dashboard/events/new    # 공연 생성
   └─ /dashboard/events/[id]
      ├─ /overview             # 공연 개요 / 상태 / 기본 설정
      ├─ /seats                # 좌석 관리
      ├─ /ticket-types         # 티켓 타입 / 가격
      ├─ /feed                 # 공연 피드 관리
      ├─ /reservations         # 예매자 목록 / 입금 승인 / 취소 / 대기열
      └─ /check-in             # QR 체크인
```

---

## 2. 관객 화면 구조

## 2-1. 홈 피드
### 목적
- 공연 발견
- 공연 홍보 게시글 소비
- 공연 상세로 유입

### 주요 컴포넌트
- 상단 브랜드 헤더
- 공연 피드 카드 리스트
- 공연 카드/피드 카드 클릭 시 공연 상세 이동

---

## 2-2. 공연 상세 페이지
### 목적
- 공연 정보 확인
- 공연별 피드 확인
- 예매 CTA 제공

### 주요 섹션
- 포스터 / 공연명 / 일시 / 장소 / 가격 요약
- 상세 설명
- 공연 상세 피드
- 예매하기 버튼

---

## 2-3. 예매 페이지
### 선착순 공연
- 티켓 타입 선택
- 매수 선택
- 신청자 정보 입력
- 조회 패스워드 설정
- 계좌 안내

### 좌석 지정 공연
- 좌석 선택 UI
- 티켓 타입 선택
- 신청자 정보 입력
- 조회 패스워드 설정
- 계좌 안내

---

## 2-4. 승인 여부 확인 페이지
입력값:
- 이름
- 연락처
- 조회 패스워드

결과:
- 승인 대기 / 승인 완료 상태
- 승인 완료 시 예매번호 표시

---

## 2-5. 예매 상세 조회 페이지
입력값:
- 이름
- 연락처
- 조회 패스워드

결과:
- 예매 정보
- QR
- 취소 버튼(가능 시간 내)

---

# 3. 기획자 화면 구조

## 3-1. 대시보드 홈
### 목적
전체 운영 현황을 빠르게 파악한다.

### KPI 카드 예시
- 총 공연 수
- 예정 공연 수
- 진행 중 공연 수
- 종료 공연 수
- 총 예매 수
- 입금 대기 수
- 예매 확정 수
- 오늘 체크인 수
- 대기 신청 수

### 보조 영역
- 최근 생성한 공연
- 오늘 공연 요약

---

## 3-2. 공연 목록 화면
### 목적
내가 만든 공연을 상태별로 관리한다.

### 리스트 컬럼 예시
- 공연명
- 공연 날짜
- 상태
- 예매 수
- 입금 대기 수
- 체크인 수

---

## 3-3. 공연 상세 운영 화면 탭 구조

### 탭 1. 개요
- 공연 기본 정보
- 상태 변경
- 공개 URL 복사
- 취소 마감 시간 수정

### 탭 2. 좌석
- 좌석 생성
- 좌석 목록 확인

### 탭 3. 티켓 타입
- 일반 / 학생 / VIP 등 생성 및 수정

### 탭 4. 피드
- 공연 피드 게시글 작성 / 수정 / 삭제

### 탭 5. 예매
- 예매자 목록 테이블
- 입금 승인
- 취소 처리 확인
- 대기 신청 목록 확인
- 대기자 전환

### 탭 6. 체크인
- 휴대폰 카메라 QR 스캐너
- 후면 카메라 기본 사용
- 카메라 권한 허용 / 실패 상태 처리
- 체크인 결과 로그

---

# 4. 가장 중요한 화면 우선순위

## 우선순위 1: 대시보드 홈
통계형 KPI가 가장 먼저 보여야 한다.

## 우선순위 2: 공연 상세 > 예매 탭
실무 운영의 핵심은 예매자 목록 테이블이다.

---

# 5. UI 구현 메모

## 예매자 목록 테이블 필수 액션
- 입금 승인 버튼
- 상태 필터
- 검색
- 대기자 전환 버튼
- 행 클릭 시 상세 모달

## 체크인 화면 필수 UX
- 카메라 미리보기
- 후면 카메라 우선 실행
- 카메라 선택 / 다시 시도 버튼
- 스캔 성공 시 잠시 스캐너 일시 정지
- QR 인식 성공/실패 메시지
- 이미 입장한 QR 경고
