# 더미데이터 작성 지침

이 문서는 Homely Arts의 샘플·데모 데이터를 만들거나 수정할 때 적용하는 기준이다. 서비스의 핵심 배경은 **대학가 및 소규모 공연**이다.

## 1. 공연 규모와 배경

- 대학 동아리, 학생 창작팀, 독립 기획팀이 준비할 법한 공연을 기본으로 한다.
- 장소는 교내 강당·연습실, 대학가 소극장, 독립 서점, 소형 라이브 클럽처럼 구체적으로 설정한다.
- 객석은 대체로 20~~150석, 티켓은 무료 또는 약 5,000~~35,000원 범위가 자연스럽다.
- 아레나, 대형 페스티벌, 거대한 LED 무대, 수천 명의 관객, 유명 연예인 중심의 묘사는 사용하지 않는다.

## 2. 공연 상세 설명과 피드의 역할

두 콘텐츠는 같은 문장을 복사해서 사용하지 않는다.

### 공연 상세 설명

- 작품의 배경과 기획 의도, 출연 또는 참여 팀, 러닝타임과 프로그램을 자세히 설명한다.
- 입장 시간, 좌석 방식, 촬영 가능 여부, 지각 입장 등 실제 관람에 필요한 정보를 포함한다.
- 관객이 예매를 결정할 수 있을 정도로 구체적이고 충분한 분량으로 작성한다.

### 공연 피드

- 홈 화면에서 관심을 끌기 위한 광고·홍보 콘텐츠다.
- 한 게시글에는 한 가지 소식이나 메시지만 담고, 짧은 문구와 명확한 이미지를 사용한다.
- 리허설 한 장면, 출연진 공개, 마감 임박, 셋리스트 일부 공개처럼 시의성 있는 소재를 쓴다.
- 상세 설명이나 관람 수칙 전체를 피드에 그대로 옮기지 않는다.
- 공연당 대표 피드 1개만 작성하며 공연 상세 페이지에는 노출하지 않는다.

## 3. 이미지 기준

- 포스터, 상세 이미지, 피드 이미지는 각각의 용도에 맞는 서로 다른 이미지로 준비한다.
- 실제 대학생 또는 신진 창작자의 소규모 제작 환경이 느껴져야 한다.
- 낮은 무대, 가까운 객석, 간소한 조명, 직접 만든 소품, 연습실과 리허설 장면을 우선한다.
- 대형 공연장, 과도한 특수효과, 빽빽한 대규모 군중, 고가의 투어 장비가 중심인 이미지는 제외한다.
- 생성형 이미지는 워터마크·브랜드 로고·읽을 수 없는 가짜 문자를 넣지 않는다.
- 실제 인물이나 단체로 오해할 수 있는 고유 로고와 실존 공연 포스터는 사용하지 않는다.
- 전체 더미 공연은 최종 20개로 확장하며, 추가 공연 14개 중 7개만 포스터 이미지를 홈 피드에도 재사용한다. 나머지는 별도의 피드 사진을 사용한다.

### 생성 프롬프트 공통 규칙

- 사진은 대학생 동아리원이나 소규모 창작팀이 휴대폰 또는 보급형 미러리스 카메라로 직접 촬영한 수준으로 요청한다.
- 천장 가까이에서 내려다보는 공중 샷, 크레인 샷, 드론 샷, 대형 스튜디오 세팅, 광고 촬영 수준의 과도한 조명과 보정을 제외한다.
- 자연스러운 눈높이, 객석이나 연습실 구석, 무대 옆, 테이블 건너편처럼 실제 팀원이 접근할 수 있는 촬영 위치를 사용한다.
- 약간의 손떨림, 고르지 않은 실내 조명, 생활감 있는 배경, 직접 만든 소품과 케이블 등 소규모 제작 환경의 현실적인 흔적을 허용한다.
- 인물은 전문 모델처럼 정교하게 포즈를 취하지 않고 리허설, 설치, 대화, 악기 정리 등 실제 준비 행동을 한다.
- 포스터는 인쇄 가능한 세로 키비주얼이되 읽을 수 없는 가짜 문자를 생성하지 않도록 텍스트 없는 이미지로 만든다.

### 공연 상세 이미지 프롬프트 규칙

- 공연의 내용과 공간을 이해할 수 있는 한 장면을 사용한다. 연습실 전체, 소품이 놓인 무대, 출연진의 자연스러운 리허설처럼 관객이 공연 분위기를 예상할 수 있어야 한다.
- 전문 공연 사진가의 결정적 순간보다 팀원이 준비 과정에서 기록한 사진처럼 자연스럽게 구성한다.
- 상세 설명을 읽는 흐름에 맞게 `4:3`, `3:2`, `16:9` 가로 비율을 우선하고, 얼굴과 핵심 소품이 잘리지 않게 한다.

### 홈 피드 이미지 프롬프트 규칙

- 두 문장 안팎의 짧은 피드 문구와 함께 보았을 때 즉시 공연의 분위기가 전달되는 단일 소재를 선택한다.
- 별도 피드 사진은 리허설 중 한 장면, 직접 만든 소품, 공연 직전 준비처럼 친근하고 가까운 거리의 기록 사진으로 만든다.
- 포스터를 피드에 재사용하는 공연은 별도 피드 이미지를 만들지 않고 동일한 포스터 파일을 참조한다.

### 이미지 비율

- 상세 이미지는 지나치게 긴 세로 이미지를 기본값으로 사용하지 않는다.
- 휴대폰과 일반 카메라에서 자연스러운 `16:9`, `4:3`, `3:2` 가로 사진이나 `4:5`, `3:4` 세로 사진을 우선한다.
- 포스터처럼 세로 비율 자체가 콘텐츠의 형식인 경우에는 `2:3` 또는 A계열 용지에 가까운 비율을 사용할 수 있다.
- 공연마다 가로와 세로 사진을 적절히 섞되, 한 공연 안에서는 화면의 역할에 맞게 비율을 정한다. 상세 공간 소개는 가로 사진, 인물이나 포스터 강조는 세로 사진이 자연스럽다.
- 비율을 맞추기 위해 인물의 얼굴·악기·주요 소품이 어색하게 잘리거나 사진이 과도하게 늘어나지 않게 한다.

### 공연 간 이미지 다양성

- 모든 공연을 무대 위 공연 장면으로만 채우지 않는다.
- 공연의 성격에 따라 공식 포스터, 출연진 단체사진, 연습실 사진, 무대 설치, 의상·소품, 객석과 공간, 공연 직전의 준비 장면 등을 선택한다.
- 같은 공연 장면을 사용하더라도 정면 전체 무대, 객석 뒤 와이드숏, 무대 옆 시점, 연주자 클로즈업처럼 촬영 구도를 달리한다.
- 조명과 분위기도 공연마다 구분한다. 따뜻한 자연광, 차가운 연습실 조명, 흑백 기록 사진, 밝은 교내 축제, 어두운 소극장처럼 작품의 성격에 맞게 선택한다.
- 서로 다른 공연에 동일한 인물 구성, 무대 배치, 색감, 카메라 위치를 반복하지 않는다.
- 이미지 세트를 만들기 전에 해당 공연의 `대표 소재`, `촬영 구도`, `화면 비율`, `조명·분위기`를 정하고 기존 샘플과 겹치지 않는지 확인한다.

## 4. 기획자와 예매 정보

- 기획자명, 단체명, 장소명, 예매자명은 한국에서 자연스럽게 보이는 가상 정보로 작성한다.
- 연락처, 이메일, 계좌번호, 오픈채팅 주소는 실제 개인에게 연결되지 않는 명백한 샘플 값만 사용한다.
- 은행명과 입금자명, 요청 사항, 환불 안내가 서로 모순되지 않게 작성한다.
- 예매 요청 사항은 좌석 접근성, 일행 동반, 입장 시간처럼 소규모 공연에서 실제로 생길 법한 내용으로 쓴다.
- 비밀번호는 개발·시연 전용임을 전제로 하고 운영 계정에 재사용하지 않는다.

### 2차 추가 공연 계획

- `종이별의 지도` 제거 후 최종 공연 19개, 피드 19개로 구성한다.
- 최종 기획사는 15개이며 모든 기획사는 공연을 최대 2개까지만 소유한다.
- 신규 기획사 9개 중 `오비트 사운드`만 공연 2개를 맡고 나머지 8개 기획사는 공연 1개씩 맡는다.
- 신규 10개 공연은 모두 대표 이미지를 가진다. `각주 없는 밤`, `반 박자 느린 우리`, `여섯 번째 테이크`, `붙였다 떼는 마음`의 대표 이미지는 제목이 들어간 세로 포스터다.
- 상세 이미지는 `각주 없는 밤`, `오후 네 시의 화음`, `처음 만드는 축제`, `창문을 빌려드립니다`, `엔딩 크레딧 이후` 5개 공연에만 둔다.
- `오후 네 시의 화음`, `여섯 번째 테이크`, `창문을 빌려드립니다`, `오늘의 대사는 없습니다`는 대표 이미지를 피드에서도 재사용한다. 나머지 6개 공연은 별도 피드 이미지를 사용한다.
- 장르는 `연극`, `뮤지컬`, `음악`, `무용/댄스`, `전시`, `강연/토크`, `영화/영상`, `기타` 중 하나만 사용한다.

| 공연 | 기획사 | 장르 |
| --- | --- | --- |
| 각주 없는 밤 | 페이지 스테이지 | 연극 |
| 오후 네 시의 화음 | 오비트 사운드 | 음악 |
| 계단 아래 콘서트 | 오비트 사운드 | 음악 |
| 반 박자 느린 우리 | 느린걸음 프로젝트 | 무용/댄스 |
| 여섯 번째 테이크 | 프레임 클럽 | 영화/영상 |
| 처음 만드는 축제 | 작은탁자 기획단 | 강연/토크 |
| 창문을 빌려드립니다 | 룸세븐 컬렉티브 | 전시 |
| 붙였다 떼는 마음 | 캠퍼스 캔버스 | 전시 |
| 오늘의 대사는 없습니다 | 수업뒤 제작소 | 기타 |
| 엔딩 크레딧 이후 | 라이트박스 시네마 | 영화/영상 |

샘플 초기화는 `scripts/db/reset-and-seed-sample.mjs`를 사용한다. 이미지 자산은 `public/demo/<공연 식별자>/`에 공연별로 보관한다.
