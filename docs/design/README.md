## 1. 문서 사용법

이 문서는 기존 ASCII 도면을 수정하지 않고 해석·색인한 정규화 디자인 명세다. 원본 ASCII와 기존 통합 메모는 [`source/`](./source/)에 보존한다. Codex는 화면을 구현하거나 수정할 때 다음 순서로 읽는다.

1. 이 문서의 공통 정책을 확인한다.
2. 라우트 인덱스에서 대상 화면 ID를 찾는다.
3. 해당 화면의 데이터, 컴포넌트, 액션, 상태를 확인한다.
4. 세부 비즈니스 규칙은 연결된 PRD 문서를 따른다.

충돌 시 우선순위는 다음과 같다.

1. 사용자가 최근 확정한 요구사항
2. PRD 기능·보안·데이터 정책
3. 이 디자인 명세
4. 화면 예시 데이터

예시 공연명, 인물명, 날짜, 가격은 레이아웃 설명용이며 제품 정책이 아니다.

### 1.1 원본 보존 인덱스

각 ASCII 문서는 원문 전체를 `text` 코드 블록에 넣었다. `원본 SHA-256`은 코드 블록 본문만 추출해 계산한 값이며 변환 전 파일과 동일하다.

| 기존 파일                      | Markdown 원본                                                                     | 화면           | 보존 검사         |
| ------------------------------ | --------------------------------------------------------------------------------- | -------------- | ----------------- |
| `design/1.txt`                 | [`01-home.ascii.md`](./source/01-home.ascii.md)                                   | A-01 홈 피드   | SHA-256 일치      |
| `design/2.txt`                 | [`02-event-detail.ascii.md`](./source/02-event-detail.ascii.md)                   | A-02 공연 상세 | SHA-256 일치      |
| `design/3.txt`                 | [`03-reservation-drawer.ascii.md`](./source/03-reservation-drawer.ascii.md)       | A-03 예매      | SHA-256 일치      |
| `design/4.txt`                 | [`04-pending-ticket.ascii.md`](./source/04-pending-ticket.ascii.md)               | A-05 입금 대기 | SHA-256 일치      |
| `design/5.txt`                 | [`05-confirmed-ticket.ascii.md`](./source/05-confirmed-ticket.ascii.md)           | A-05 예매 확정 | SHA-256 일치      |
| `design/7.txt`                 | [`07-reservation-dashboard.ascii.md`](./source/07-reservation-dashboard.ascii.md) | O-10 예매 관리 | SHA-256 일치      |
| `design/8.txt`                 | [`08-super-admin-excluded.ascii.md`](./source/08-super-admin-excluded.ascii.md)   | MVP 제외       | SHA-256 일치      |
| `design/9.txt`                 | [`09-event-create.ascii.md`](./source/09-event-create.ascii.md)                   | O-05 공연 생성 | SHA-256 일치      |
| `gemini-code-1783664275343.md` | [`legacy-integrated-spec.md`](./source/legacy-integrated-spec.md)                 | 기존 통합 메모 | 파일 SHA-256 일치 |

복원된 파일 세트에는 `6.txt`가 없다. 기존 통합 메모는 `6.txt`를 좌석 목록 화면으로 참조하지만 원문 유효성을 검사할 파일이 없으므로, O-06 명세는 PRD와 기존 통합 메모를 기준으로 정규화했다.

### 1.2 원본 유효성 평가

| 검사 영역      | 결과      | 설명                                                                                                                             |
| -------------- | --------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 원문 보존      | 통과      | 복원된 ASCII 8개와 기존 통합 MD의 해시가 변환 전후 동일하다.                                                                     |
| 단일 가격      | 통과      | 홈, 상세, 예매, 공연 생성 도면이 공연 단일 가격 정책과 일치한다.                                                                 |
| 상태명         | 통과      | 입금 대기와 예매 확정 도면이 PRD 상태와 일치한다.                                                                                |
| 비회원 조회    | 통과      | 공연 컨텍스트와 이름·연락처·조회 패스워드 흐름이 일치한다.                                                                       |
| 좌석           | 통과      | 복수 좌석 선택과 점유 상태가 PRD의 `reservation_seats` 흐름과 호환된다.                                                          |
| 운영 대시보드  | 부분 상세 | 원본 도면은 핵심 컬럼과 액션을 보여주지만 PRD의 티켓 타입·금액·체크인 시각 등 전체 컬럼은 생략한다. 정규화 명세 O-10에 보완했다. |
| 좌석 관리 원본 | 검증 불가 | `6.txt`가 복원되지 않아 ASCII 원문 보존 여부를 평가할 수 없다.                                                                   |
| MVP 제외       | 통과      | Super Admin과 자동 취소를 제공하지 않는다는 정책이 일치한다.                                                                     |

원본 도면은 시각적 레이아웃 자료이고, 이 문서의 화면별 섹션은 원본에서 생략된 PRD 요구사항을 보완한 구현 계약이다. 원본과 보완 명세 중 하나를 삭제하거나 서로 덮어쓰지 않는다.

## 2. 확정된 공통 정책

| 항목      | 정책                                                                                                        |
| --------- | ----------------------------------------------------------------------------------------------------------- |
| 사용자    | Organizer, Audience, System만 사용한다. Super Admin은 MVP에서 제외한다.                                     |
| 관객 인증 | 회원가입 없이 공연 컨텍스트 + 이름 + 연락처 + 숫자 4~6자리 조회 패스워드를 사용한다.                        |
| 가격      | 타입이 있으면 타입별 가격, 없으면 공연 기본 가격을 사용한다. 총액은 `unit_price × quantity`다.              |
| 티켓 타입 | 일반·학생 등의 선택적 등급이며 개별 가격을 설정한다. 별도 재고는 없다.                                      |
| 좌석      | A1, A2 같은 단순 라벨 목록을 사용한다. 좌석 등급, 통로 편집, 공연장 맵 편집은 제외한다.                     |
| 좌석 점유 | 입금 대기부터 좌석을 점유한다. 취소 시 `released_at`을 기록해 점유를 해제한다.                              |
| 결제      | 무통장 입금만 사용하며 자동 입금 확인과 결제 게이트웨이는 제외한다.                                         |
| 발급      | 입금 승인 후에만 예매번호와 정적 QR을 발급한다.                                                             |
| 체크인    | QR 1개는 티켓 1매(좌석 1석)를 나타낸다. 일행별 개별 입장이 가능하며 전원 입장 시 예매 전체를 완료 처리한다. |
| 취소      | 공연별 취소 마감 전 직접 취소할 수 있다. 영구 삭제 대신 상태와 좌석 이력을 보존한다.                        |
| 인기 공연 | 관객 평점 없이 예매 수를 기준으로 정렬한다.                                                                 |
| 자동화    | 장기 미입금 자동 취소와 자동 대기자 승계는 제외한다.                                                        |

## 3. 디자인 시스템

### 3.1 레이아웃

- 모든 화면은 사각형 카드와 명확한 경계선을 사용하는 Box Grid 스타일을 따른다.
- 관객 화면은 모바일 퍼스트로 설계한다.
- 기획자 화면은 데스크톱 퍼스트이며 고정 사이드바와 넓은 작업 패널을 사용한다.
- 관객용 대표 포스터는 A3 세로 비율인 `1:1.414`를 유지한다.
- 모바일 예매 입력은 하단 드로어 또는 바텀시트로 표시한다.

## 5. 관객 화면

### A-01. 홈 피드

목적: 공연 발견과 공연 상세 유입.

데이터:

- 추천 공연
- 예매 수 기준 인기 공연
- 장르 목록
- 공개 공연과 공연별 피드 게시글

컴포넌트 순서:

1. 브랜드 헤더
   - 로그인
   - 기획자 회원가입
   - 예매 조회
2. 추천 공연 히어로
   - 공연명, 단체명, 기간, 장소
   - `지금 바로 예매하기`
3. 인기 공연 카드 목록
   - 포스터, 공연명, 단체명, 단일 가격
4. 장르 필터
   - 전체, 연극, 뮤지컬, 밴드/음악, 전통/무용
5. 통합 공연 피드
   - 포스터 또는 피드 이미지, 본문 요약, 기간, 단일 가격
   - `상세보기 및 예매`

상태:

- 로딩 스켈레톤
- 공개 공연 없음
- 장르 필터 결과 없음

PRD: `section-04-feature-requirements.md` 기능 C, `section-05-dashboard-and-pages.md` 2-1.

### A-02. 공연 상세

목적: 공연 정보 확인, 피드 소비, 예매 시작.

데이터:

- 공연명, 공개 상태, 장소, 시작·종료 시각, 러닝타임
- A3 비율 대표 포스터와 선택적 상세 이미지
- 단일 티켓 가격
- 잔여 좌석 또는 선착순 잔여 수량
- 예매 방식, 최대 매수, 취소 마감
- 은행명, 계좌번호, 예금주
- 공연별 피드 게시글

컴포넌트 순서:

1. 공유 링크 복사
2. 공연명과 공개 상태
3. 포스터와 핵심 정보 카드
4. 상세 설명과 상세 이미지
5. 공연별 피드
6. 예매·판매 정책
7. 예매 CTA
   - 좌석 지정: `좌석 선택하고 예매하기`
   - 선착순: `매수 선택하고 예매하기`
   - 매진: `대기 신청하기`

규칙:

- `HIDDEN`, `CANCELLED` 공연은 공개 상세에서 접근할 수 없다.
- 잔여 수량은 서버 계산값을 표시한다.
- 입금 계좌는 예매 과정에서도 최종 금액과 함께 다시 보여준다.

PRD: `section-04-feature-requirements.md` 기능 B·C, `section-05-dashboard-and-pages.md` 2-2.

### A-03. 비회원 예매

목적: 좌석 또는 매수 선택부터 예매 신청까지 한 흐름에서 완료.

공통 필수 입력:

- 이름
- 연락처
- 입금자명
- 숫자 4~6자리 조회 패스워드
- 예매 매수

선택 입력: 요청사항.

좌석 지정 흐름:

1. 활성 좌석 목록에서 복수 좌석 선택
2. 점유 좌석은 비활성 표시
3. `quantity = seatIds.length`로 자동 동기화
4. 티켓 타입이 있으면 타입 선택
5. 신청자 정보 입력

선착순 흐름:

1. 잔여 수량 안에서 매수 선택
2. 티켓 타입이 있으면 타입 선택
3. 신청자 정보 입력

금액과 제출:

1. 선택한 티켓 타입의 `price × quantity`를 실시간 표시하며 타입이 없으면 기본 `ticket_price`를 사용
2. `계좌 정보 확인` 후 은행명, 계좌번호, 예금주, 최종 입금액 표시
3. `입금 완료 및 최종 예매 신청`
4. 서버가 가격·잔여 수량·좌석 점유를 재검증
5. 성공 시 `PENDING_PAYMENT` 상태 화면으로 이동

오류:

- 좌석 동시 선점 실패
- 잔여 수량 부족
- 최대 매수 초과
- 패스워드 형식 오류
- 취소되었거나 종료된 공연

PRD: `section-04-feature-requirements.md` 기능 D, `section-07-api-and-actions.md` `createReservation`.

### A-04. 승인 여부 확인

목적: 입금 승인 여부와 승인 후 예매번호 확인.

컨텍스트와 입력:

- URL 쿼리의 `eventSlug`
- 이름, 연락처, 조회 패스워드

결과:

- 입금 대기: 예매번호·QR 미노출
- 예매 확정: 예매번호 노출, 상세 조회 CTA
- 후보 복수 건: 신청 시각·매수 등 최소 정보로 후보 선택
- 조회 실패: 개인정보 존재 여부를 과도하게 노출하지 않는 오류

PRD: `section-02-users-and-roles.md` 4, `section-08-auth-and-security.md` 3.

### A-05. 예매 상세·QR·취소

목적: 예매 정보, QR, 취소 가능 여부 확인.

공통 표시:

- 상태, 공연명, 관람 시각
- 매수와 선택 좌석
- 예매자, 입금자명, 결제금액
- 취소 마감 시각

상태별 표시:

| 상태      | 예매번호                       | QR             | 액션                       |
| --------- | ------------------------------ | -------------- | -------------------------- |
| 입금 대기 | 발급 대기                      | 안내 문구      | 취소 가능 시 취소          |
| 예매 확정 | 표시                           | 고유 정적 QR   | 취소 가능 시 취소          |
| 취소      | 기존 번호가 있으면 참조용 표시 | 무효           | 주최자 환불 문의 안내      |
| 입장 완료 | 표시                           | 사용 완료 표시 | 체크인 완료 시각 표시      |
| 대기 신청 | 없음                           | 없음           | 대기 취소 정책에 따른 액션 |

QR 규칙:

- 개인정보가 아닌 추측 불가능한 `qr_token`만 인코딩한다.
- 캡처 여부는 판별하지 않는다.
- 예매 매수만큼 QR을 나누어 표시하며 좌석 지정 공연은 각 좌석명을 함께 표시한다.
- 이미 체크인된 개별 QR은 재사용할 수 없고 같은 예매의 다른 QR은 독립적으로 사용할 수 있다.

PRD: `section-04-feature-requirements.md` 기능 D·F, `section-08-auth-and-security.md` 4.

## 6. 기획자 화면

### O-01·O-02. 회원가입과 로그인

회원가입 필드: 이메일, 비밀번호, 이름, 연락처, 단체명.<br>
로그인 필드: 이메일, 비밀번호.

규칙:

- 성공 시 보호된 `/dashboard`로 이동한다.
- 실패 시 필드 오류 또는 일반 인증 오류를 표시한다.
- Audience 회원가입과 소셜 로그인은 제공하지 않는다.

### O-03. 전체 통계 대시보드

KPI:

- 총·예정·진행 중·종료 공연 수
- 입금 대기·예매 확정·대기 신청 수
- 오늘 체크인 수

보조 영역: 최근 생성 공연, 오늘 공연 요약.

### O-04. 공연 목록

컬럼: 공연명, 날짜, 상태, 예매 수, 입금 대기 수, 체크인 수.<br>
액션: 공연 생성, 상태 필터, 공연 상세 진입.

### O-05. 공연 생성 Step 1

필드:

- 공연명, 장르, 장소, 시작·종료 시각, 러닝타임
- 대표 포스터 URL/업로드, 상세 이미지 URL/업로드, 상세 설명
- 예매 방식
- 단일 티켓 가격
- 선착순 선택 시 총 수용 인원
- 1인 최대 예매 매수
- 선택적 티켓 타입 목록
- 좌석 지정 공연은 최초 생성 단계에서 행·열 수와 통로·빈 공간을 포함한 좌석 배치도
- 취소 마감
- 은행명, 계좌번호, 예금주

동적 규칙:

- 선착순: `total_capacity` 필수.
- 좌석 지정: `total_capacity` 입력을 숨기고 활성 좌석 수를 사용.
- 좌석 지정: 생성 화면의 배치도에서 활성 좌석을 선택하고 저장된 행·열 위치를 관객 좌석 선택 화면에 유지.
- 좌석별 가격은 구분하지 않으며 선택한 티켓 타입 가격을 사용.

액션:

- 임시 저장: `HIDDEN`
- 다음: 좌석 지정이면 O-06, 선착순이면 미리보기
- 미리보기: 공개 데이터에 노출하지 않고 A-02 컴포넌트를 재사용
- 공개: 필수값 검증 후 `SCHEDULED`

### O-06. 좌석 목록

컴포넌트:

- 좌석 라벨 입력과 추가 버튼
- 무대 기준 N×N 좌석 배치도
- 각 좌석 셀에서 라벨, 활성 여부, 점유 상태 확인과 수정·비활성화
- 미리보기, 임시 저장, 공개

규칙:

- `(event_id, label)`은 중복될 수 없다.
- 최초 공개 전에는 좌석 배치도를 전체 교체할 수 있다.
- 최초 공개 후에는 공연을 다시 비공개로 바꾸더라도 좌석 배치를 읽기 전용으로 표시한다.
- 예매 이력이 있는 좌석은 영구 삭제하지 않고 비활성화한다.
- 행×열 생성과 좌석 셀 활성/해제로 통로·빈 공간을 표현한다.
- 좌석 등급과 좌석별 차등 가격은 제공하지 않는다.

### O-07. 공연 개요

- 기본 정보와 단일 가격 수정
- 상태 변경
- 공개 URL 복사
- 취소 마감 수정
- 임시 저장, 미리보기, 공개

가격 변경은 신규 예매에만 적용하며 기존 `unit_price`, `total_price`는 유지한다.

### O-08. 티켓 타입 관리

- 일반·학생 같은 분류값 추가·수정·삭제
- 가격·재고 필드 없음
- 티켓 타입을 하나도 만들지 않을 수 있음

### O-09. 피드 관리

- 공연별 게시글 작성·수정·삭제
- MVP 게시글은 이미지 1개와 본문으로 구성
- 공개 공연의 게시글만 홈·공연 상세 피드에 노출

### O-10. 예매·입금·대기열 관리

상단:

- 관리 공연 선택
- 총 예매 매수·매출, 입금 대기 건수, 예매 확정 건수, 잔여 좌석/수량
- 입금자명·연락처 검색, 상태 필터

테이블 컬럼:

- 선택, 예매자, 연락처, 매수, 선택 좌석, 티켓 타입
- 입금자명, 결제금액, 예매 상태, 체크인 상태·시각, 신청 시각

행 액션:

- 입금 대기: 승인, 취소
- 예매 확정: 승인 취소, QR 조회, 취소
- 대기 신청: 예매 전환, 취소
- 입장 완료: 상세 조회만 허용

일괄·보조 액션:

- 일괄 입금 승인
- 일괄 취소
- 현재 검색·필터 범위 엑셀 다운로드
- 페이지네이션과 페이지 크기 선택

규칙:

- 영구 삭제하지 않는다.
- 승인 시 고유 예매번호와 `qr_token`을 생성한다.
- 승인 취소 시 QR을 즉시 무효화한다.
- 입장 완료 건은 승인 취소·일괄 취소 대상에서 제외한다.

### O-11. QR 체크인

컴포넌트:

- 카메라 미리보기
- 후면 카메라 우선, 카메라 선택
- 권한 실패·비지원·비HTTPS 오류와 다시 시도
- 성공·실패·중복 입장 메시지
- 최근 체크인 로그와 완료 시각

흐름:

1. QR의 `qr_token` 감지
2. 스캐너 일시 정지
3. 현재 공연과 Organizer 소유권 검증
4. 해당 티켓의 `checked_in_at`을 기록하고 모든 티켓이 입장했으면 예약도 `CHECKED_IN`으로 변경
5. 취소·대기·입금 대기 QR은 거부
6. 이미 사용된 QR은 기존 완료 시각을 유지하고 중복 입장 경고

## 7. 공통 예외와 빈 상태

- 네트워크 실패: 입력값을 보존하고 재시도 제공
- 권한 없음: 로그인 또는 관리 가능한 공연으로 이동
- 이미지 실패: 고정 비율 플레이스홀더 표시
- 목록 없음: 다음 행동을 안내하는 빈 상태 CTA 표시
- 개인정보: 연락처는 필요한 운영 화면 외에는 최소 노출
- 파괴적 액션: 취소·승인 취소 전 확인 다이얼로그 표시

## 8. MVP 제외

- Super Admin과 글로벌 제어 화면
- 공연 강제내림과 기획자 계정 발급
- 장기 미입금 자동 취소
- 관객 평점, 좋아요, 댓글, 팔로우, 알림
- 결제 시스템과 자동 입금 확인
- 좌석 등급·좌석별·티켓 타입별 차등 가격
- 공연장 맵 에디터와 통로 편집
- 일괄 영구 삭제
- QR 캡처 판별 또는 회전형 QR
